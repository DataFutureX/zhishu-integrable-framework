一句话架构

DeepSeek Harness 是一棵由 profile 组合出来的 Cordis 插件树：没有特权内核，模型适配器、工具注册表、会话日志、 agent 循环本身全都是插件，注册即 effect，插件卸载即回滚。一个 append-only 的 session log 是模型上下文的唯一权威来源； 每项能力以 Service Definition / Service Provider / Consumer 三件套的「缝」存在，换一个 provider 就整体改变产品行为； web / headless / sdk / sdk-minimal / acp 五个 profile 只是同一棵树的五套层叠。

包331 个 workspace 包（packages/<group>/<pkg>，含 test-support）
应用apps/cli（唯一 Node 启动器）、apps/web、apps/desktop、apps/desktop-host
内核vendored Cordis（vendor/），插件 = 服务 + typed events + 可回滚 effect
权威数据SessionEvent 日志，用 deriveMessages() 投影出模型历史
不变量Model-visible ⟺ logged：进模型请求的东西必须能从日志重建
缝约 30 个 ctx 缝/服务，provider 可替换，consumer 通常是模型可见工具

1

入口 / 启动

受支持的 Node 应用只能通过命名的 dsh profile 启动
dsh CLIapps/cli · @deepseek-ai/dsh唯一支持的应用启动器：dsh --profile <name> / dsh web / dsh plugin。只解析自己的 flag，其余原样交给 profile 内的 app 插件。禁止 package bin、demo、SDK argv 逃逸。
Desktopapps/desktop + apps/desktop-hostElectron 外壳包住完整的 dsh Web 应用：私有 Desktop Host 以 Electron Node 模式跑共享 CLI profile runner，窗口直接加载打包的 Web 资源，Node IPC 传 boot injection / readiness / shutdown。
浏览器前端apps/web（Vite → dist）Web shell 与 client 插件 bundle 的构建产物；由 host/frontend-static 在 HTTP 兜底席位提供，不是独立应用（__DSH_BOOT__ 只能由 dsh 注入）。
SDK 客户端packages/sdk/client · python/TS 客户端以命名 profile + 有序 patch 启动 dsh 子进程；Python 运行时 wheel 打包同一个 dsh CLI 并默认选 sdk。
ACP 客户端packages/acp仅自动化的 Agent Client Protocol stdio 服务，同样是一个 profile 而不是新 bin。

组合与引导

运行中的 dsh = 启动时按有序层组合出来的一棵插件树
Profile$DSH_HOME/profiles/<name>一个目录：package.json（dsh.profile.bundles 有序列表 + 树外插件依赖）与用户自己的 cordis.patch.yml。模板：web / headless / sdk / sdk-minimal / acp；desktop 名字保留给 Electron。
Bundlepackages/bundle/*可安装的 patch 层分发格式（dsh.bundle 指向 patch 文件）。dsh-base 是共享第一层；web-app / headless / sdk-app / acp-app 叠在其上；sdk-minimal 是刻意的例外，一棵完整独立的显式树，不套 base。
Patchcordis.patch.yml按行 id 定位并整体替换该行的 config，或插入新行。preset patch 把同样的操作做在某个声明的 config.plugins 里，层优先级一致。
app-bootpackages/boot/app-boot从 cordis.yml 引导应用：加载 .env、应用 profile/patch 各层、启动 Loader、把启动失败报清楚。提供 ctx.profileContext。
hmrpackages/boot/hmr · ctx.hmr协调模块与配置的 watcher 和重载，并给自己的改动排入同一条队列；base 默认开启（仅配置），headless / SDK / ACP 关闭，sdk-minimal 不含。
cmdline / config-editor / plugin-managerpackages/boot/*应用自有参数与退出码；把配置改动持久化进 profile patch 并让 Loader 对账；当前 profile 的插件与 bundle 包管理（与 dsh plugin 共享包操作和写锁）。
presetpackages/preset · ctx.agentPresets把「agent 平面」（工具、提示词、技能）从进程级搬进逐会话声明：web bundle 的 presets/standard|ptc|minimal|cordis 各自是一份 patch，按会话选择并保留退役 revision。
▼Loader 把每一行挂成插件；插件向共享 ctx 注册服务、事件与 effect
3

Cordis 运行时

扩展 dsh 的唯一方式：在别的插件旁边再挂一个插件
Service插件向 ctx 提供具名服务，消费方用 ctx.<name>（声明式注入）或 ctx.get(name)（可选服务）读取。服务可被替换，这是缝的基础。
Typed events声明合并出来的事件映射。waterfall 监听器必须调用 next() 才能继续委派，否则短路；serial 事件（如 agent/turn-stopping）没有 next()。
Effects每一次贡献都走 ctx.effect() / ctx.on()，注册函数返回 disposer；卸载插件时贡献回滚，这也是 HMR 安全性的来源。
Scopepackages/core/scope：把注册限定到某一个 agent 的作用域原语，是「同一进程、不同会话看到不同能力集」的实现基础。
▼所有产品行为都长在这些扩展点上
4

核心脊柱

packages/core + packages/llm/llm —— 可替换的产品 API 主干
agent-loopctx.agentLoop · packages/core/agent-loop唯一的具体驱动：创建 agent、跑 turn/step 生命周期、冻结并发送请求、派发工具、处理重试与压缩恢复。扩展包依赖 dsh-agent 的事件与服务，而不是依赖它。
agentctx.agents · packages/core/agent公开的 Agent 契约：活体句柄注册表、create/resume 工厂缝、agent/* 事件、inbox 与 initiator 传播。
sessionctx.sessions · packages/core/sessionappend-only 的 SessionEvent 日志与内存存储；deriveMessages() 从它投影出模型历史，fork/resume/transcript/telemetry 全部从这些持久结算派生。
toolsctx.tools · packages/core/tools分作用域的工具注册表 + 受控执行管线：pre-policy → 单调守卫 → 围绕式 dispatch → post-policy → 终态观察；同时拥有 PTC 模式传输。
system-promptctx.systemPrompt把有序段落、工具 schema 与变量组装成模型请求里的提示词；每个工具的能力 schema 在这里汇入组装。
llmctx.llm · packages/llm/llm消息与流词汇（Message / BlockAssembler / StreamChunk）+ adapter 缝；循环与压缩只调用 provider 中立的流服务。
agent-default-modelctx.agentDefaultModel部署默认模型选择；入口在会话没有自己的选择时套用它。
▼脊柱只依赖缝的 Service Definition，具体能力由下面的 provider 补上

表面（Host / Remote API / Client / 其他协议面）

流式会话数据刻意走在 Remote 调用之外
host/webserverctx.webServer纯 node:http 载体：具名路由注册表、index 变换 tap、静态 dist 兜底席位。
host/frontend-static消费 ctx.webServer在兜底席位提供构建后的 SPA dist；前端没构建就直接启动失败并给构建提示。

api/* 控制器ctx.*Controllersession / workspace / settings / terminal / job / workspace-files / account：各自拥有 Host 侧行为，只把描述符交给 gateway 传。
Client 数据对象层无 Reactconnection 拥有传输世代；api-session-controller/client 拥有 ClientSessions → SessionManager → Session；workspace-controller/client 拥有 Workspace 状态；client/store 提供快照存储引擎。

SDK 面sdk/protocol · sdk/server换行分隔的 JSON-RPC over stdio；客户端可开会话、发提示、观察 session 事件、agent 状态与子代理完成。
ACP 面packages/acp仅自动化使用；也为它自己的 agent 充当批准应答者。
headless 面ctx.headless-runner一次任务、无服务器：跑一个全新的持久会话、打印最终答案、退出。

Service Provider可替换实现（例：fs-local / fs-sandbox / fs-ssh）
↓ 被使用
Consumer通常是模型可见工具（例：tool-fs 的全部读写改都经 ctx.fs）
  • 一个角色不是缝：只有三者齐备，才算一个可替换能力；三者只在独立演进时才拆成不同包。
  • 缝的威力在组合：fs 与 subprocess 指向同一个执行世界，所以把它们一起指向远程沙箱，Bash、PTY、LSP 会跟着搬走，不需要 provider 分支。
  • Service Definition 要为所有当前 consumer 设计：工具 schema、UI、Loader、传输、provider 特有行为都留在 consumer 或 provider 里。
  • 默认值必须是显式的 resolve(request): Spec 步骤，落在拥有该能力的实现里，而不是 run() 里的隐藏 ?? default。

图 D · Turn / Step 生命周期

step = 一次模型请求加上它调用的工具；turn = 零个或多个 step，在第一次输入被 claim 之前打开，在没有任何欠账时关闭。 实线 = 持久 session 事件 虚线 = 进程内活动扩展点

打开turn/start
取输入claim：next-step 输入 + 一条排队消息
组装system-prompt/assemble（段落 + 工具 schema）→agent/pre-step ◆→enter(messages) | reject
被拒、或第一批被改写成空 → 这个已经打开的 turn 不花任何 step 就关闭
开步step/start
定路由agent/request ◆→prepareCall(config, signal)
这两段异步阶段里发生取消 → system 与 user 两边都不提交
准入system/message→user/message→request/header · request/context（按需）
冻结从日志推导并冻结模型历史
流式llm/stream ◆→agent/assistant-stream: start → chunk* → end
结算assistant/message|assistant/attempt（失败/重试/取消/流错误的持久结算，不进模型历史）
工具tool/call*→tools/pre-execute ◆→tools/execute ◆→tools/post-execute ◆→tool/result*
按 executionMode 分类，屏障 + 有界滚动池，开始前重新分类；按模型顺序出结果
收步step/end
再循环还有欠的请求，或 next-step 输入到达 → 回到 claim
停轮agent/turn-stopping（serial，无 next()）
关闭turn/end

◆ = waterfall 事件，监听器必须调用 next() 才能继续委派，直接返回即短路。重试发生在同一个已打开的 step 内：重新 prepareCall 并重新对账，但不重复组装，也不重复 agent/pre-step 与 user 准入。

图 E · 三条事件域与唯一权威源

session events持久事实
用法需要活过重载的事实
通道追加进日志并通过 session/event 广播；turn/*、step/*、system/message、user/message、assistant/message、assistant/attempt、tool/*
消费者fork、resume、transcript、遥测、持久化、客户端重放
agent/*活体协调
用法观察或拦截飞行中的工作
通道携带活的 Agent：inbox、step、status、request、validation、continuation、request-error
注意是活的协调 API，不是可回放转录；agent/assistant-stream 的 chunk 帧是瞬态的
capability events策略与适配器
用法把策略/适配器挂到一条缝上，而不去 import 循环
通道fs/*、tools/*、telemetry/*、approval/request、compaction/*、workflow/* 等

Model-visible ⟺ logged。每一个模型请求都必须能从日志重建；新的模型可见输入必须在同一改动里新增一个 session 事件。插件的模型历史贡献以「纯消息投影」注册，分离读者必须显式提供同一份定义。

由此推出三条硬边界：assistant/message 内嵌产生它的完整紧凑定时流；assistant/attempt 保留未成消息的失败/重试/取消/流错误结算；进程在结算前丢失则不留持久 attempt 流。
