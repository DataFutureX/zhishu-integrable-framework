# LetsWork 桌面客户端接入模型网关 `/v1` 指南

> 面向 LetsWork（Electron / Node）桌面端开发者。
> 目标：登录后仅用一个 Base URL + 一个 Bearer token，完成「拉模型目录 → 选模型 → 流式推理 → 展示额度」，并正确处理额度耗尽、模型下线、上游异常等失败。
> 服务端设计见 `zhishu-backend/docs/model-gateway-design.md`；对端插件契约见 `lets-work-desktop/custom/plugins/dsh-plugin-model-gateway/docs/design.md`。

## 1. 概览

```
LetsWork（桌面端）
   │  Authorization: Bearer <知枢 JWT>
   ▼
模型网关（知枢后端 /v1）
   │  校验 JWT → 选模型 → 扣减/预留额度 → 协议适配
   ▼
真实供应商（OpenAI / DeepSeek / 通义千问 / …）
```

要点：

- **只有一套协议**：OpenAI 兼容，三个端点。
- **只有一个凭据**：知枢登录 JWT；供应商密钥只在服务端。
- **额度由服务端权威计算**：客户端不参与计量，只展示 `/v1/quota` 与处理 429。
- **上游模型名不外泄**：响应中的 `model` 会被改写为网关 `model_id`。

## 2. 前置条件

服务端需已完成：

1. `zhishu.gateway.enabled=true`（默认开启）。
2. 管理员在「模型网关 · 供应商管理」中配置供应商（Base URL + API Key），并「测试连接」通过。
3. 在「模型设置」中为该供应商添加至少一个 **对话（CHAT）** 模型，并设为默认。
4. 当前账号有可用额度（「模型网关 · 额度策略」按用户/角色/兜底配置）。

自检：浏览器或 curl 用有效 JWT 请求 `/v1/models`，能返回至少一条模型。

## 3. 基础配置

| 项 | 值 |
|---|---|
| Base URL | `http://<知枢后端>:8180`（默认开发端口；生产以部署为准） |
| 推理路径 | `POST /v1/chat/completions` |
| 目录路径 | `GET /v1/models` |
| 额度路径 | `GET /v1/quota` |
| 鉴权头 | `Authorization: Bearer <知枢 JWT>` |
| 渠道标识（可选） | `X-Zhishu-Channel: DESKTOP` |
| 客户端标识（建议） | `X-Client-Name: LetsWork`、`X-Client-Version: <版本号>` |
| 请求/响应编码 | UTF-8 |

说明：

- `X-Zhishu-Channel` / `X-Client-Name` / `X-Client-Version` 只用于服务端台账与统计，缺省不影响功能。
- **不要把 token 放在 URL 查询参数**（会被日志与代理记录）。
- 网关路径固定为**根路径 `/v1`**，不是 `/api/v1`。若经前端 Nginx 访问，必须为 `/v1/` 单独配置反向代理（见第 12 节）。

## 4. 登录与 token

沿用已有的桌面登录通道（见 `docs/Desktop登录模块接入指南.md`）：

```http
GET  /desktop/v1/auth/public-key
POST /desktop/v1/auth/login      → { "token": "<JWT>", "expiration": 1774243200000, ... }
POST /desktop/v1/auth/logout     (Authorization: Bearer <JWT>)
```

网关鉴权规则：

- JWT 缺失/格式错误/过期 → `401 invalid_api_key`
- 已登出（服务端黑名单）或改密后旧 token → `401 token_revoked`
- 账号被禁用或不存在 → `403 account_disabled`

注意：

- 没有 refresh token 接口；过期后需重新登录。
- 登出会让 token **立即**失效，网关推理随即返回 401。

## 5. 拉取模型目录

```http
GET /v1/models
Authorization: Bearer <JWT>
```

```jsonc
{
  "object": "list",
  "default": { "model": "gw-dashscope-qwen-plus" },   // 可能缺省
  "data": [
    {
      "id": "gw-dashscope-qwen-plus",
      "object": "model",
      "name": "通义千问 Plus",
      "owned_by": "dashscope",
      "created": 1760000000,
      "context_window": 131072,
      "max_output_tokens": 8192,
      "input_modalities": ["text"],
      "system_prompt_update": "in-history",
      "reasoning": { "efforts": ["low", "high"], "default_effort": "high" },
      "client_requirements": { "LetsWork": { "min_version": "0.2.1" } }
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 推理时 `model` 传这个值 |
| `name` | string | 展示名 |
| `owned_by` | string | 供应商标识，仅展示/审计用 |
| `created` | number? | 秒级时间戳，可能缺省 |
| `context_window` | number? | 上下文窗口；缺省表示未知，按保守容量处理 |
| `max_output_tokens` | number? | 单次输出上限 |
| `input_modalities` | string[]? | 支持 `text` / `image`；缺省按 `text` |
| `system_prompt_update` | string? | `in-history`：每轮都带 system；`leading-only`：仅首条带 |
| `reasoning.efforts` / `default_effort` | string[]? / string? | 可传给 `reasoning_effort` 的档位 |
| `client_requirements` | object? | 客户端版本门禁，见下 |

行为说明：

- **只下发言模型（CHAT）**；向量（EMBEDDING）模型不会出现在该接口。
- 模型或其供应商被停用后，会立刻从列表消失；此时推理返回 `404 model_not_found`。
- 顶层 `default.model` 为服务端指定的默认模型，可能缺省；缺省时客户端自行选第一条。

客户端建议：

- 登录成功后拉一次并缓存（建议 5–10 分钟），收到 `404 model_not_found` 时立即重拉。
- **版本门禁**：若存在 `client_requirements.LetsWork.min_version`，与当前版本比较；不满足则禁用该模型并提示升级，不要发送请求。
- 若 `context_window` 缺失，按保守值（如 8k–32k）做上下文裁剪，避免上游报超长。

## 6. 对话推理（非流式）

```http
POST /v1/chat/completions
Authorization: Bearer <JWT>
Content-Type: application/json
```

```jsonc
{
  "model": "gw-dashscope-qwen-plus",
  "messages": [
    { "role": "system", "content": "你是桌面助手" },
    { "role": "user", "content": "帮我总结这段代码" }
  ],
  "temperature": 0.7,
  "max_tokens": 1024,
  "tools": [],              // 可选，OpenAI 兼容 tool schema，原样透传
  "reasoning_effort": "high" // 可选，需该模型 reasoning.efforts 支持
}
```

响应要点：

- 结构与 OpenAI `chat.completion` 一致；`model` 为**网关模型 id**。
- `usage` 由上游返回：`prompt_tokens` / `completion_tokens` / `total_tokens`，可能带
  `prompt_tokens_details.cached_tokens`、`completion_tokens_details.reasoning_tokens`。
- 若请求未显式传 `temperature` / `top_p` / `max_tokens`，服务端会用该模型的默认值补齐（客户端无需感知）。
- 上游返回错误时，网关**不回传上游原始错误体**（避免泄露内部地址/密钥上下文），统一返回第 9 节的错误结构。

## 7. 对话推理（流式）

```jsonc
{ "model": "gw-dashscope-qwen-plus", "messages": [...], "stream": true }
```

响应：

- `Content-Type: text/event-stream; charset=UTF-8`
- 每帧一行 `data: {json}`，帧之间以空行分隔；结束帧为 `data: [DONE]`
- 服务端会自动向上游注入 `stream_options.include_usage=true`，因此**末帧通常带 `usage`**（此时 `choices` 为空数组）
- 服务端已设置 `X-Accel-Buffering: no` 与 `Cache-Control: no-cache`

**中断语义（重要）**：

- 只有收到 `data: [DONE]` 才算完整回答；若流提前结束（网络断开 / 上游空闲超时 / 应用退出），按「不完整回答」处理，并允许用户手动重试。
- 客户端主动断开连接时，服务端会按已输出正文估算结算额度；因此**不要为了探测而反复断开重连**。

### Node / TypeScript 示例（fetch + ReadableStream）

```ts
export interface GatewayChunk {
  choices?: Array<{ delta?: { content?: string } }>
  usage?: { prompt_tokens?: number; completion_tokens?: number; total_tokens?: number }
}

export async function streamChat(opts: {
  baseUrl: string
  token: string
  model: string
  messages: Array<{ role: string; content: string }>
  clientVersion: string
  onDelta: (text: string) => void
  signal?: AbortSignal
}): Promise<GatewayChunk['usage'] | undefined> {
  const res = await fetch(`${opts.baseUrl}/v1/chat/completions`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${opts.token}`,
      'X-Zhishu-Channel': 'DESKTOP',
      'X-Client-Name': 'LetsWork',
      'X-Client-Version': opts.clientVersion,
    },
    body: JSON.stringify({ model: opts.model, messages: opts.messages, stream: true }),
    signal: opts.signal,
  })

  if (!res.ok || !res.body) {
    const payload = await res.json().catch(() => null)
    throw Object.assign(new Error(payload?.error?.message ?? `HTTP ${res.status}`), {
      status: res.status,
      code: payload?.error?.code,
    })
  }

  const reader = res.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buffer = ''
  let usage: GatewayChunk['usage']

  while (true) {
    const { value, done } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })

    let sep = buffer.indexOf('\n\n')
    while (sep >= 0) {
      const event = buffer.slice(0, sep)
      buffer = buffer.slice(sep + 2)
      for (const line of event.split('\n')) {
        if (!line.startsWith('data:')) continue
        const payload = line.slice(5).trim()
        if (!payload) continue
        if (payload === '[DONE]') return usage
        const chunk = JSON.parse(payload) as GatewayChunk
        const delta = chunk.choices?.[0]?.delta?.content
        if (delta) opts.onDelta(delta)
        if (chunk.usage) usage = chunk.usage
      }
      sep = buffer.indexOf('\n\n')
    }
  }

  // 没收到 [DONE] 就结束：按不完整回答处理
  return usage
}
```

## 8. 额度查询

```http
GET /v1/quota
Authorization: Bearer <JWT>
```

```jsonc
{
  "unit": "tokens",
  "period": { "kind": "monthly", "reset_at": "2026-11-01T00:00:00Z" },
  "subject": { "type": "USER", "key": "zhangsan" },
  "limit": 5000000,
  "used": 3200000,
  "remaining": 1800000
}
```

说明：

- `remaining` 为 `null` 表示不限量；`limit` 同理。
- `reset_at` 为 ISO-8601（UTC），用于展示「X 月 X 日重置」。
- 该接口只用于展示，**不参与拦截**；被拒绝时以推理返回的 429 为准，此时应刷新一次额度。
- 额度按用户月度统计（角色给默认值、用户可覆盖）；用量含预留，短时间内可能略高于实际消耗。

## 9. 错误处理与重试策略

错误体统一为 OpenAI 结构：

```jsonc
{
  "error": {
    "type": "quota_exceeded",
    "code": "insufficient_quota",
    "message": "本月 token 额度已用尽，2026-11-01 重置",
    "reset_at": "2026-11-01T00:00:00Z",
    "limit": 5000000,
    "used": 5000000
  }
}
```

| HTTP | `error.type` | `error.code` | 含义 | 客户端动作 |
|---|---|---|---|---|
| 400 | `invalid_request_error` | `invalid_request_error` | 缺 `model`、JSON 非法、请求体 > 8MB | 修参数，不要重试 |
| 401 | `invalid_request_error` | `invalid_api_key` | 缺 token / token 无效或过期 | 重新登录 |
| 401 | `invalid_request_error` | `token_revoked` | token 已吊销（登出/改密） | 重新登录 |
| 403 | `permission_error` | `account_disabled` | 账号不存在或已禁用 | 提示联系管理员 |
| 404 | `invalid_request_error` | `model_not_found` | 模型不存在/已停用/供应商停用 | 刷新 `/v1/models` 并重选 |
| 429 | `quota_exceeded` | `insufficient_quota` | 本月额度用尽（带 `reset_at`/`limit`/`used`） | **不要重试**；展示额度与重置时间 |
| 429 | `rate_limit_error` | `rate_limit_exceeded` | 触发「用户×模型」QPS 限流 | 指数退避后重试（服务端未提供 `Retry-After`） |
| 429 | `upstream_error` | `rate_limit_exceeded` | **上游自身**限流（网关透传状态码） | 退避后重试；持续出现请联系管理员调整上游额度 |
| 502 | `upstream_error` | `upstream_error` | 上游返回错误（网关已归一化，不回传原文） | 提示并允许手动重试 |
| 503 | `upstream_error` | `upstream_unavailable` | 上游不可达 / 未配置 Key | 提示稍后重试 |
| 503 | `gateway_unavailable` | `gateway_not_ready` | 服务端数据库迁移未完成 | 提示联系管理员（`message` 含操作指引） |
| 504 | `upstream_error` | `upstream_timeout` | 上游超时 | 可重试一次 |

重试矩阵：

| 场景 | 是否重试 | 建议 |
|---|---|---|
| 网络错误 / 连接被重置 | 可重试 | 最多 2 次，指数退避 1s/3s |
| 502 / 503 / 504 | 可重试 | 最多 1–2 次 |
| 401 / 403 / 404 | 不重试 | 分别走重登 / 提示 / 刷新目录 |
| 429 `insufficient_quota` | **绝不重试** | 重试只会继续被拒 |
| 429 `rate_limit_exceeded` | 可重试 | 退避 1s 起 |

其他：

- **流式请求中途失败不自动重试**（会重复消耗额度）；由用户显式发起。
- 识别额度耗尽时优先用 `error.code === 'insufficient_quota'`，不要只判断 HTTP 429（限流也是 429）。

## 10. 典型时序

首次启动 / 切换账号：

1. `POST /desktop/v1/auth/login` → 保存 token 与过期时间
2. `GET /v1/models` → 缓存目录，应用 `client_requirements` 门禁，选定模型（优先 `default.model`）
3. `GET /v1/quota` → 展示剩余额度（可选）
4. `POST /v1/chat/completions`（`stream: true`）→ 增量渲染，末帧记录 `usage`

运行期异常：

| 现象 | 处理 |
|---|---|
| 401 | 清会话 → 重新登录 → 重拉目录 |
| 404 | 重拉 `/v1/models` → 若原模型消失，提示重新选择 |
| 429 `insufficient_quota` | 刷新 `/v1/quota`，展示「额度不足 + 重置时间」，禁用发送按钮直到重置或额度调整 |
| 503 `gateway_not_ready` | 展示服务端 `message`（通常要求执行迁移脚本），提示联系管理员 |

## 11. 与 dsh-plugin-model-gateway 的对应关系

若使用现有插件，无需重复实现：

| 客户端职责 | 插件实现 |
|---|---|
| 注册一条 OpenAI 兼容路由 | `api: openai-completions`、`baseURL: <base>/v1` |
| 每请求注入当前用户 JWT | `resolveAuth` / `resolveApiKey` 从账号会话取 token |
| 目录解码 | `parseModelListing`：缺字段回落默认、非法值丢弃该行 |
| 额度错误映射 | `insufficient_quota` → `QUOTA` → `ACCOUNT_QUOTA`（不重试） |
| 模型可见性 | 仅显示 `/v1/models` 返回的模型 |

插件配置示例（节选）：

```yaml
gateway:
  baseUrl: !!js process.env.ZHISHU_DESKTOP_BASE_URL || 'http://192.168.11.14:8180'
  modelsPath: /v1/models
  completionsPath: /v1/chat/completions
  quotaPath: /v1/quota
```

## 12. 限制与注意事项

| 项 | 限制 |
|---|---|
| 请求体 | ≤ 8MB（超限 400 `invalid_request_error`） |
| 连接超时 | 5s |
| 非流式总超时 | 120s |
| 流式空闲超时 | 60s（两帧之间无数据即判超时） |
| 服务端重试 | 不重试，重试责任在客户端（且不应对额度类错误重试） |
| 限流 | 默认关闭；开启后按「用户 × 模型」计 QPS（单实例语义） |
| 能力范围 | 仅对话补全；不提供 embeddings / 图片生成 |

反向代理（若经 Nginx 访问）：

- 必须为 `/v1/` 单独配置反向代理，**不能落到 SPA 的 `try_files ... /index.html`**；
- 该 location 需关闭缓冲并延长读超时，且显式透传 Host，否则 Tomcat 会因非法 Host 返回 400：

```nginx
location ^~ /v1/ {
    proxy_pass http://zhishu_backend;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}
```

其他：

- 自签证书场景需客户端显式信任，否则 `fetch` 直接报网络错误（与服务端无关）。
- 网关不会因为「没有 `usage`」而少算额度；极端情况下客户端拿不到 `usage`，不要用它做本地计费展示。

## 13. 联调自测清单

| # | 用例 | 期望 |
|---|---|---|
| 1 | 不带 `Authorization` 调 `/v1/models` | `401 invalid_api_key` |
| 2 | 用篡改过的 token 调推理 | `401 invalid_api_key` |
| 3 | 登出后用旧 token 调推理 | `401 token_revoked` |
| 4 | `/v1/models` 无默认模型 | 无 `default` 字段，客户端仍能选第一条 |
| 5 | 模型缺 `context_window` | 客户端按保守容量裁剪，不崩 |
| 6 | 非流式推理 | 200，`model` 为网关 id，带 `usage` |
| 7 | 流式推理 | 逐帧增量 + 末帧 `usage` + `[DONE]` |
| 8 | 额度耗尽 | `429 insufficient_quota`，含 `reset_at`/`limit`/`used`，且客户端不重试 |
| 9 | 停用该模型后推理 | `404 model_not_found`，客户端刷新目录 |
| 10 | 停用供应商后推理 | 同上（模型从目录消失） |
| 11 | 中文 / emoji 流式输出 | 不乱码、不截断 |
| 12 | 长回答（>60s 但持续有帧） | 不被中断 |
| 13 | 客户端中途取消 | 服务端正常收敛，无残留请求 |
| 14 | `client_requirements` 高于当前版本 | 客户端禁用该模型并提示升级 |

## 14. FAQ

**Q1：为什么 `/v1/models` 只返回一个模型？**
看「模型设置」里该供应商下是否有多个 **CHAT** 模型，以及目标模型是否为启用状态；向量模型不会出现在这里。

**Q2：`default` 字段缺失怎么办？**
说明服务端未设置默认模型；客户端按 `sort_order` 取第一条，或记住用户上次选择。

**Q3：能直接用 OpenAI 官方 SDK 连吗？**
可以（`baseURL` 设为 `<base>/v1`，`apiKey` 设为知枢 JWT）；但要注意 401/429 的语义来自本文第 9 节。

**Q4：为什么流式最后一帧没有正文？**
那是带 `usage` 的统计帧（服务端强制上游 `include_usage`），`choices` 为空属正常现象，不要当异常。

**Q5：客户端需要自己算 token 吗？**
不需要。额度完全由服务端计算与强制，客户端只展示 `/v1/quota` 与处理 429。

**Q6：能否用 `model` 传供应商真实模型名（如 `qwen-plus`）？**
不能。`model` 必须是 `/v1/models` 返回的 `id`；真实模型名只存在于服务端目录中。

**Q7：出现 `gateway_not_ready` 怎么办？**
服务端数据库结构未对齐（`ai_gateway_model` 缺列等）。把返回的 `message` 转给运维：先确认启动日志中
`db/init_gateway.sql` 与 `db/gateway_schema.sql`（非破坏性结构对齐）是否执行成功；历史库还需按顺序手工执行
`db/patch_provider_model_split.sql` 与 `db/patch_drop_model_legacy.sql`（见 `zhishu-backend/README.md` 升级脚本清单）。
