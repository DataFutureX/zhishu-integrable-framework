# 云起应用平台 · 单点登录对接说明

**版本：** 1.0  
**日期：** 2026-08-19  
**状态：** 已落地（换票接口与回调页按本文实施）  
**适用对象：** 万象、数智 IoT 等需登录云起后台的伙伴系统，以及云起前后端实现方

本文约定：**伙伴系统签发短期 ticket → 云起验签换票 → 签发云起业务 JWT**。  
这不是企业级 OIDC 统一身份平台，而是可信系统之间的单向互信登录。

---

## 1. 概述

### 1.1 目标

已在伙伴系统登录的用户，无需再输入云起账号密码，即可进入云起应用平台（YQAP / 云起后台），并使用云起本地 RBAC（角色、菜单、按钮权限）。

第一期支持的来源：

| 伙伴 | 建议 `iss` | 说明 |
|------|------------|------|
| 万象 | `wanxiang` | 从万象进入云起 |
| 数智 IoT | `shuzhi-iot` | 从数智 IoT 进入云起 |

后续新增来源只登记伙伴与公钥，**不新增换票接口**。

### 1.2 范围

**包含：**

- 万象 / 数智 IoT → 云起 的单向 SSO
- Ticket 格式、密钥分工、换票 API、前端回调、用户映射、错误码、联调清单

**不包含（后续另开文档）：**

- 云起作为 IdP 给其它系统发号
- 云起 → 万象 / 数智 IoT 的反向单点
- OIDC / CAS / SAML 企业 IdP 接入
- 首次登录自动建号（JIT）

### 1.3 与现有登录的关系

云起当前登录为：RSA 加密用户名密码 + 滑动验证码 → 签发 JWT。  
SSO **只替换「如何确认身份」**，确认后仍使用现有 `JwtUtil` 签发业务 JWT，后续鉴权不变。

| 通道 | 验证码 | 登录 RSA 公钥 | 密码 | 结果 |
|------|--------|----------------|------|------|
| 本地登录 `POST /api/v1/auth/login` | 需要 | 需要（加密凭证） | 需要 | 云起业务 JWT |
| 伙伴 SSO `POST /api/v1/auth/sso/exchange` | 不需要 | **不使用** | 不需要 | 同一套云起业务 JWT |

**禁止**把现有 `GET /api/v1/auth/public-key` 当作 SSO 密钥。该接口仅用于登录页加密用户名和密码。

本地登录与 SSO 可并存（HYBRID）。是否在登录页展示账号密码表单，由产品配置决定，不影响换票协议。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 云起 / YQAP | 云起应用平台后台（本仓库），验票并签发业务 JWT |
| 伙伴 | 万象、数智 IoT 等已登记的来源系统 |
| Ticket | 伙伴用私钥签发的短期 JWT，仅用于换票，不能调云起业务接口 |
| 业务 JWT | 云起用自身密钥签发的登录 Token，与密码登录成功后的 Token 相同 |
| `iss` | Ticket 签发方标识，用于选择公钥 |
| `aud` | Ticket 接收方，固定为 `yunqi-application-platform` |
| `jti` | Ticket 唯一 ID，云起用过即作废，防止重放 |
| `kid` | 密钥 ID，用于公钥轮换 |

密钥方向（必须遵守）：

| 动作 | 钥匙 |
|------|------|
| 伙伴 **签发** ticket | 伙伴 **私钥**（只放在伙伴侧） |
| 云起 **校验** ticket | 该伙伴的 **公钥**（只登记在云起） |
| 云起 **签发** 业务 JWT | 云起 `jwt.secret`（**永不交给伙伴**） |

口诀：私钥在谁手里，谁才能冒充谁。公钥不能用来「生成」可被信任的 ticket。

## 3. 总体流程

```
已登录用户          伙伴服务                 云起前端                  云起后端
    |                 |                       |                         |
    | 点击进入云起     |                       |                         |
    |---------------->|                       |                         |
    |                 | 私钥签发 ticket        |                         |
    |                 | 302 / 打开回调 URL     |                         |
    |---------------------------------------->|                         |
    |                 |                       | POST /api/v1/auth/sso/exchange
    |                 |                       |------------------------>|
    |                 |                       |  按 iss 取公钥、验签      |
    |                 |                       |  校验 aud / exp / jti    |
    |                 |                       |  查 sys_user、状态        |
    |                 |                       |  签发业务 JWT             |
    |                 |                       |<------------------------|
    |                 |                       | 写入 token，拉 /users/me |
    |                 |                       | 进入系统（与本地登录相同） |
```

原则：

1. Ticket 只换票，不能当 `Authorization: Bearer` 访问业务 API。
2. 换票成功后的会话、权限、菜单、路由守卫与本地登录完全一致。
3. 所有伙伴共用同一个换票接口与同一个前端回调页。

## 4. 密钥与伙伴登记

### 4.1 密钥算法

- 算法：`RS256`（RSA + SHA-256）
- 密钥长度：至少 2048 bit，推荐 3072 或 4096
- 每个伙伴独立密钥对，**禁止**万象与数智 IoT 共用一把钥

### 4.2 生成示例（OpenSSL）

在伙伴侧生成（私钥不出伙伴机房）：

```bash
openssl genrsa -out partner-private.pem 2048
openssl rsa -in partner-private.pem -pubout -out partner-public.pem
```

将 `partner-public.pem` 交给云起运维登记；`partner-private.pem` 不得进入云起仓库、配置中心或工单附件。

### 4.3 公钥轮换

1. 云起为同一 `iss` 配置多把公钥，以 `kid` 区分。
2. 伙伴在 JWT Header 带上 `kid`。
3. 新钥生效后，旧钥保留至少一个 ticket 最大存活周期，再下线。

### 4.4 云起配置骨架

```yaml
yunqi:
  sso:
    enabled: true
    audience: yunqi-application-platform
    clock-skew-seconds: 30
    jti-ttl-seconds: 180          # ≥ ticket 最大存活 + 时钟差
    partners:
      wanxiang:
        enabled: true
        issuer: wanxiang
        display-name: 万象
        algorithm: RS256
        public-key: classpath:sso/wanxiang.pem
        # 轮换时可改为按 kid 映射多把公钥
        ticket-ttl-max-seconds: 120
        username-claim: username   # 缺省则回退 sub
      shuzhi-iot:
        enabled: true
        issuer: shuzhi-iot
        display-name: 数智IoT
        algorithm: RS256
        public-key: classpath:sso/shuzhi-iot.pem
        ticket-ttl-max-seconds: 120
        username-claim: username
```

`iss` 最终字符串须与各伙伴书面确认；上表为建议值。未登记或 `enabled: false` 的来源一律拒绝。

`jti` 已用集合：单机可用内存；多实例必须外置（如 Redis），TTL 与 `jti-ttl-seconds` 一致。建议存储键为 `{iss}:{jti}`，避免两家 UUID 碰撞。

## 5. Ticket 规范

伙伴签发的 JWT 必须符合下列约定。

### 5.1 Header

```json
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "wanxiang-2026"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `alg` | 是 | 仅允许 `RS256`，其它算法拒绝 |
| `typ` | 是 | `JWT` |
| `kid` | 建议 | 对应该伙伴在云起登记的公钥 ID；单钥阶段也可省略 |

数智 IoT 示例：`"kid": "shuzhi-iot-2026"`。

### 5.2 Payload

万象示例：

```json
{
  "iss": "wanxiang",
  "aud": "yunqi-application-platform",
  "sub": "zhangsan",
  "username": "zhangsan",
  "name": "张三",
  "iat": 1774156800,
  "nbf": 1774156800,
  "exp": 1774156860,
  "jti": "8f3c1a2e-4b9d-4c6a-9e21-1a2b3c4d5e6f"
}
```

数智 IoT 示例：仅将 `iss` 改为 `shuzhi-iot`，其余字段集合保持一致。

| 字段 | 必填 | 说明 |
|------|------|------|
| `iss` | 是 | 必须等于云起已登记的伙伴 issuer |
| `aud` | 是 | 固定 `yunqi-application-platform` |
| `sub` | 是 | 伙伴侧稳定用户标识（登录名或工号） |
| `username` | 建议 | 映射云起 `sys_user.username`；缺省则使用 `sub` |
| `name` | 否 | 显示名，第一期可不写入用户表 |
| `iat` | 是 | 签发时间，Unix 秒 |
| `nbf` | 建议 | 生效时间，通常等于 `iat` |
| `exp` | 是 | 过期时间。建议 `iat + 60` 秒，**不得超过 `iat + 120` 秒**，且不得超过该伙伴 `ticket-ttl-max-seconds` |
| `jti` | 是 | UUID。同一 `iss + jti` 只能换票一次 |

时间校验允许时钟偏差 ±`clock-skew-seconds`（默认 30 秒）。

### 5.3 明确禁止

- 使用云起登录 RSA 公钥加密一段 JSON 充当 ticket
- 使用对称算法（HS256）且与云起 `jwt.secret` 相同
- 把业务 JWT 当 ticket，或把 ticket 当业务 JWT
- 有效期按「会话级」拉到数小时、数天
- 在 ticket 中放入密码、完整身份证号等敏感明文（无必要）

## 6. 浏览器跳转

伙伴在用户已登录的前提下，打开云起前端回调地址：

```
{YUNQI_WEB}/sso/callback?ticket={ticket}&redirect=/dashboard
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `ticket` | 是 | 第 5 节 JWT 字符串，需 URL 编码 |
| `redirect` | 否 | 登录成功后的云起**站内相对路径**，如 `/dashboard`。缺省进入默认首页 |

约束：

- `{YUNQI_WEB}` 为云起前端源站，例如 `https://yunqi.example.com`，由环境约定，禁止开放任意外域。
- `redirect` 必须是以 `/` 开头的相对路径，不得包含 `://`、`//`、反斜杠跳转等，防止开放重定向。
- Ticket 出现在 URL 中仅用于一次性跳转。云起前端换票成功后须立刻用 `history.replaceState`（或等价路由 replace）去掉 query 中的 `ticket`。
- 推荐 HTTPS。生产环境不得走明文 HTTP。

服务端对服务端可直接调用换票接口，再由伙伴把云起业务 JWT 交给己方前端。仍**不推荐**把业务 JWT 放在 URL 查询参数中长期传递。

## 7. 换票接口

### 7.1 基本信息

| 项 | 值 |
|----|-----|
| 方法 / 路径 | `POST /api/v1/auth/sso/exchange` |
| 登录态 | 不需要 |
| 验证码 | 不需要 |
| Content-Type | `application/json` |
| 安全放行 | 须加入 Spring Security 公开路径（与 `/api/v1/auth/**` 一致） |

所有伙伴共用此接口，用 ticket 的 `iss` 区分来源。

### 7.2 请求体

```json
{
  "ticket": "<伙伴签发的 JWT>",
  "redirect": "/dashboard"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ticket` | string | 是 | 完整 JWT |
| `redirect` | string | 否 | 回显给前端作跳转目标，**不参与鉴权**。后端仍须按第 6 节规则校验后原样或规范化返回 |

### 7.3 成功响应

与现有统一响应 `Result` 及登录成功字段对齐，便于前端复用 token 写入逻辑：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "<云起业务 JWT>",
    "expiration": 1774243200000,
    "redirect": "/dashboard"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `token` | string | 云起业务 JWT，用法与 `POST /api/v1/auth/login` 返回的 `token` 相同 |
| `expiration` | number | 过期时间，**毫秒时间戳**，与现有 `LoginResponseDTO.expiration` 一致 |
| `redirect` | string | 合法的站内路径；未传或非法时返回默认首页路径 |

前端处理：

1. 将 `token`、`expiration` 写入现有 `localStorage`（键名 `token`、`tokenExpiration`）。
2. 请求 `GET /api/v1/users/me` 与当前用户权限/菜单接口（与本地登录相同）。
3. 跳转到 `data.redirect`。
4. 后续请求在 `Authorization` 头携带 `Bearer <token>`。

### 7.4 失败响应

```json
{
  "code": 401,
  "message": "SSO 票据无效或已过期",
  "data": null
}
```

业务错误使用 `Result.code`（与现有接口一致，未必等于 HTTP 状态码）。建议如下：

| 场景 | `code` | `message`（示例） |
|------|--------|-------------------|
| `ticket` 为空或非 JWT 格式 | 400 | 票据不能为空 |
| `redirect` 非法（有外域形态） | 400 | 回调地址不合法 |
| 签名失败 / `alg` 不是 RS256 | 401 | 票据签名无效 |
| `iss` 未登记或伙伴未启用 | 403 | 未开通该来源的单点登录 |
| `aud` 不匹配 | 401 | 票据接收方不正确 |
| 尚未生效或已过期 | 401 | 票据无效或已过期 |
| 存活时长超过伙伴上限 | 401 | 票据有效期超出限制 |
| `jti` 已使用 | 401 | 票据已使用 |
| 用户不存在 | 401 | 账号未开通，请联系管理员 |
| 用户禁用 | 403 | 账号已被禁用，请联系管理员 |
| 系统未开启 SSO | 403 | 未开启单点登录 |

实现时 `message` 可对终端用户保持简短，详细原因打在服务端日志（勿把验签细节回给浏览器）。

## 8. 云起校验顺序

必须按下列顺序执行，任一步失败立即拒绝且**不**签发业务 JWT：

1. SSO 总开关 `yunqi.sso.enabled` 为 true。
2. `ticket` 非空，按 JWT 解析 Header / Payload（解析失败则 400/401）。
3. `alg` 为 `RS256`。
4. 用 `iss` 查找伙伴；不存在或未启用则拒绝。
5. 按 `kid`（或该伙伴默认钥）取公钥，验签。
6. `aud` 等于全局 `yunqi.sso.audience`。
7. 校验 `nbf` / `exp`，含时钟差；`exp - iat` 不超过该伙伴 `ticket-ttl-max-seconds`。
8. 将 `{iss}:{jti}` 写入已用集合（原子「不存在则写入」）；已存在则拒绝。
9. 取用户名：`username-claim` 指定字段，空则 `sub`。
10. 按 `sys_user.username` 查询用户；不存在则拒绝（第一期不做 JIT）。
11. `status == 1`（启用）；否则拒绝。
12. `JwtUtil.generateToken(username)` 签发业务 JWT。
13. 写登录审计，来源为伙伴编码（见第 11 节）。

**不**走滑动验证码，**不**走登录 RSA 加解密，**不**走密码失败锁定（锁定仅作用于本地密码通道）。

## 9. 用户映射

### 9.1 第一期规则

```
ticket.username（无则 sub）  ==  sys_user.username
```

- 账号由云起管理员预先开通并授权角色。
- 同一自然人从万象和数智 IoT 进入时，若用户名相同，则进入**同一个**云起账号、同一套权限。
- 禁用用户即使验签成功也不得登录。

双方必须书面约定：**伙伴侧登录名（或用于 `username`/`sub` 的字段）与云起用户名一致。**

### 9.2 用户名体系不一致时（非第一期默认）

仅当两家无法统一登录名时，再增加映射，例如：

- 伙伴配置 `username-claim` 指定用工号还是邮箱；
- 或增加 `sys_user` 外部标识（`idp` + `external_id`）对照表。

第一期不启用自动建号。若未来开启 JIT，须单独规定默认角色、默认组织、以及是否允许各伙伴自动建号。

## 10. 云起前端回调页

| 项 | 约定 |
|----|------|
| 路径 | `/sso/callback` |
| 鉴权 | 匿名可访问（路由白名单） |
| 来源 | 不区分万象 / 数智 IoT |

处理步骤：

1. 读取 query 中的 `ticket`、`redirect`。
2. 无 `ticket`：提示参数错误，提供返回登录页。
3. `POST /api/v1/auth/sso/exchange`。
4. 成功：`setToken(token, expiration)`，拉取用户信息与权限，跳转 `redirect`。
5. 失败：展示接口 `message`，提供返回登录页。
6. 无论成败，尽快从地址栏移除 `ticket`。

演示模式（`VITE_DEMO_MODE`）下应关闭真实换票或使用 Mock，避免连到生产伙伴密钥。

## 11. 审计与可观测

登录审计在现有登录审计之上增加来源字段（或在失败原因/渠道中区分）：

| 渠道 | 建议编码 |
|------|----------|
| 本地密码 | `LOCAL` |
| 万象 SSO | `WANXIANG` |
| 数智 IoT SSO | `SHUZHI_IOT` |

成功、失败均记录：用户名（能解析时）、客户端 IP、User-Agent、渠道、结果、失败原因。  
验签失败时用户名可能为空，仍记录 `iss`（若可解析）与原因类别。

## 12. 安全要求

1. **HTTPS** 传输 ticket 与业务 JWT。
2. 伙伴私钥与云起 `jwt.secret` 分级保管，禁止入库明文。
3. Ticket 一次性（`jti`）且短过期。
4. 校验 `iss`、`aud`、`exp`、`nbf`、算法白名单，防止套用到其它系统或改用 `none`/HS256。
5. `redirect` 仅允许站内相对路径。
6. 换票接口限流（按 IP / 按 iss），降低爆破与重放噪音。
7. 日志禁止打印完整 ticket、私钥、业务 JWT。
8. 用户禁用、删除后，已发出的业务 JWT 仍按现有黑名单/过期机制失效；SSO 不能绕过禁用检查。

---

## 13. 登出

第一期：云起登出仍为 `POST /api/v1/auth/logout`（业务 JWT 入黑名单），**不**自动登出万象或数智 IoT。  
反向登出（云起退出同时结束伙伴会话）不在本期范围。

## 16. 伙伴签发伪代码

以下仅说明逻辑，语言不限。

```text
now = unix_seconds()
payload = {
  iss:      "<wanxiang | shuzhi-iot>",
  aud:      "yunqi-application-platform",
  sub:      "<与云起 username 一致>",
  username: "<与云起 username 一致>",
  name:     "<可选>",
  iat:      now,
  nbf:      now,
  exp:      now + 60,
  jti:      random_uuid()
}
header = { alg: "RS256", typ: "JWT", kid: "<已登记 kid>" }
ticket = jwt_sign_rs256(header, payload, partner_private_key)

url = "{YUNQI_WEB}/sso/callback?ticket=" + url_encode(ticket) + "&redirect=/dashboard"
redirect_browser(url)
```
