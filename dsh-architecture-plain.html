DeepSeek Harness 是用什么拼出来的，一次对话又是怎么跑的

这一版刻意不用术语。读完你应该能回答五个问题：它是怎么拼起来的、一次对话怎么跑、为什么换零件不用改代码、东西存在哪、你屏幕上的界面是怎么来的。

先说清楚

这是一份通俗说明，不是规范。想知道精确的包名、ctx 键、事件名和分层图，看旁边那份严谨版。两份讲的是同一件事。

右上角有个「朗读本页」按钮，用的是你浏览器自带的语音，不联网也能用。表格和对照表不会被念出来。

01它不是"一个程序"，是一棵"插件树"

大多数软件长这样：一个主程序，外加一些可有可无的插件。DSH 不是。

在 DSH 里，连"主程序"本身都是插件。负责跟模型说话的、负责记日志的、负责管理工具的、负责决定"这一轮该怎么问模型"的那个循环——全都是插件，平等地挂在同一块底板上。没有任何一块是"必须先有的核心"。

这么设计只为了一个目的：想让它多一种能力，你不需要去改核心。你在旁边再插一块就行。而且插上去的每一块都能拔下来——拔掉之后，它在运行期间做过的事会自动撤销干净。这一点在开发时特别有用：改一个文件，整个程序不用重启。

对应术语

底板是 Cordis（一套插件框架）。一块插件挂上去时会"提供服务、监听事件"，这些动作都登记成可撤销的效果，所以卸载 = 干净回滚。整棵树的构成写在 docs/architecture.md。

02每次启动，它先"拼装"，再运行

启动的那一刻，它手里只有一张空白清单，然后一层一层往上贴：

  1. 基础层。把所有入口共用的一套能力贴上去：跟模型对话、读写文件、跑命令、记日志、沙箱与审批、设置、凭据、遥测。
  2. 入口层。再贴上你这个入口专用的那一包。网页、命令行一次性任务、SDK、ACP，各是一包。
  3. 你自己的覆盖。你在 profile 目录里写的那个覆盖文件。
  4. 机器级覆盖。跨 profile 生效的全局覆盖。
  5. 临时覆盖。命令行上给的 --patch。

贴的方式很直白：按名字找到那一行，整行换掉。所以结论是——内置配置没有任何一行是神圣不可改的。你可以先让它把最终清单打印出来，再挑一行覆盖；打印出来的每一行都能被你替换。

有一个例外值得记住：sdk-minimal 是"全套自己带"的一包，不贴基础层。它图的是最小，代价是能力也最少。

打个比方

像拼乐高：基础层是通用零件袋，入口层是主题零件袋，覆盖文件是你在说明书边上手写的批注，--patch 是这次临时决定换个轮子。后贴的批注永远压过前面的印刷。

03一次对话到底是怎么跑的

只需要两个词：

  • 一步：问模型一次，加上它这一次要用的工具全部跑完。
  • 一回合：从"有活儿要干"开始，到"什么都不欠了"结束。一回合里可能有零步、一步，也可能有很多步。

然后是流水线，从上到下：

  1. 取活儿。拿一条你交给它的事，顺手带上你排队发的消息，打开一个回合。
  2. 备料。把"系统提示词"和"这一步能用哪些工具"拼出来。
  3. 让插件看一眼。插件可以在这里改写你要发出去的内容，也可以直接拒掉。如果被拒、或者内容被改成了空，这个回合就不花任何一步，直接关掉。
  4. 定路线。决定这一步走哪个模型、哪个端点。这一小段是异步的：如果这时候被取消，前面准备的东西一个都不提交。
  5. 记账。把系统提示和你说的话按顺序记进账本，然后把这次请求"冻结"下来——冻结之后它就不可变了。
  6. 问模型。开始流式接收。模型要么回一段话，要么点一个工具。
  7. 跑工具。先检查能不能跑，再并发执行，最后按模型给的顺序把结果记下来。
  8. 还欠着吗？工具结果得回给模型、或者你又在旁边发了新消息——那就回到第 1 步，再来一步。
  9. 收工。没有欠账了，关掉这个回合。

这条流水线最关键的地方在于：每一步都留了挂钩。插件挂在挂钩上，就能看见、能改写、能拦截。所以给 DSH 加功能，永远是"挂一个钩子"，而不是"改那个循环"。

对应术语

挂钩分成两类：一类是永久记在账上的事实（回合开始/结束、每一步的开始/结束、你说的话、模型说的话、工具调用与结果）；另一类只存在于进程内存里，用于实时协作（收件箱、状态、拦截请求、流式片段）。判断标准很简单：这件事需不需要在重开程序之后还活着？

04为什么换零件不用改代码

每一个"可以换掉的东西"，都被拆成三个角色，缺一不可：

  • 定义——说清楚"这个能力长什么样"。像墙上插座的孔型标准。
  • 实现——真正干活的那一个。像插上去的电器。
  • 消费者——用它的人。像用电的设备。

规矩是：只有定义，不算能换。三个角色齐了，才叫一个"缝"。这条规矩听起来啰嗦，但它把"我在配置里加个开关"和"我真的能换掉整块能力"区分开了。

最有说服力的例子是文件、进程、沙箱这三件事。它们指向的是同一个世界：文件在哪读、命令在哪跑、跑的时候受什么限制，本来就是一件事的三个面。所以你把这三样一起指向一台远程机器，Bash、终端、代码跳转就会全部跟着搬过去——用它们的那些工具，一行代码都不用改。

你想换掉的东西现在有哪些实现可选
跟谁说话DeepSeek 官方接口、其他兼容接口、回放（给测试用，不真的联网）
读写哪些文件本地、受沙箱限制、远程 SSH
命令在哪跑本地 Bash、沙箱里的 Bash、PowerShell、远程
怎么上网查DeepSeek 搜索、Exa、Perplexity、直接抓网页
子任务交给谁本进程新开一个、把当前会话分叉一份、交给别的产品（Codex / Claude Code）、交给 SDK
会话存在哪文件（默认）、换成别的后端

05东西存在哪：一本只往后加的账本

一次会话里发生的一切，都记在一本账上，只往后加，不改也不删。

模型每一轮"看到的历史"，不是另存的一份副本，而是从这本账重新算出来的。这就推出了一条贯穿全局的铁律：模型能看到的东西，必须在账上。如果你想往提示词里塞一个新东西，那得先在账本里加一种新条目——没有例外。

换来的是省心：换台机器打开、程序重开、把某一段对话复制成一个新会话、事后做分析和检索——全部都从同一本账出发，不会出现"界面显示的和模型记得的不一样"。

为什么值得

把"界面"和"事实"彻底分开之后，界面就可以随便重写（它只负责怎么画），而不会影响模型到底看到了什么。这也解释了为什么改一个工具卡片的样式，不需要动模型行为。

06你屏幕上的界面是怎么来的

三条路，同一个内核：

  • 网页 / 桌面。后台进程起一个 HTTP 服务（启动时给一个一次性令牌，之后用签名 Cookie，并且校验来源），浏览器里跑的也是同一棵插件树的一部分；两边通过一条 RPC 通道说话。流式输出的数据量最大，所以它单独走一条通道，不挤在 RPC 里。
  • 命令行一次性任务。不起服务器，跑完把结果打印出来就退出。
  • 被别的程序调用。SDK 和 ACP 都是"换个开门方式"，内核和上面前两条完全一样。

桌面版不是第二套实现：它是一个 Electron 外壳，里面装的还是同一个内核和同一套网页资源，只是顺手接管了原生窗口、系统对话框、快捷键和自动更新。

浏览器这一侧自己也分了三层，而且只能单向依赖：管数据的（不碰界面）、管渲染的（唯一把数据变成界面的地方）、管长相的（拿到什么画什么，不自己去找数据）。这样拆的好处是：换一套视觉效果，不需要动数据逻辑。

08几个容易误会的地方

  • "它是个带插件系统的程序。" —— 不是，它本身就是插件拼起来的，没有特权内核。
  • "沙箱是把危险功能关掉。" —— 不是，是把即将执行的命令包一层再执行，执行完报告有没有真的限制住。
  • "系统提示词是一份固定文件。" —— 不是，每一步现拼，拼的内容可以被插件改写。
  • "界面改了就等于行为改了。" —— 不是，界面只管怎么画；能影响模型的输入必须落账。
  • "工具的大输出会直接塞进对话。" —— 不会，超大文本和图片各有着落：落到磁盘，只给模型一个引用。
  • "改配置必须重启。" —— 基础层默认开了配置热重载，改完会自动重新拼装一次。
  • "重试会重来一遍之前的步骤。" —— 不会，重试发生在同一个已打开的步里，不重复备料，也不重复"让插件看一眼"。
