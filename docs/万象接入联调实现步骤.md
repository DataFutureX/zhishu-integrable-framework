# 万象接入云起 · 单点登录联调实现步骤

**版本：** 1.0  
**日期：** 2026-08-19  
**适用：** 万象（`iss=wanxiang`）→ 云起应用平台 单向 SSO  
**总规范：** 详见同目录 [单点登录对接说明.md](./单点登录对接说明.md)

本文给出**可照着做的联调步骤**：云起侧准备、万象侧改造、本地 / 测试 / 生产三套地址约定，以及验收用例。

---

## 0. 约定一览（双方签字确认）

| 项 | 约定值 | 说明 |
|----|--------|------|
| `iss` | `wanxiang` | Ticket 签发方，云起配置必须一致 |
| `aud` | `yunqi-application-platform` | 固定，不可改 |
| `kid` | `wanxiang-2026` | 首把公钥 ID；轮换时双方同步更新 |
| 算法 | `RS256` | RSA ≥ 2048 bit |
| 用户名 | 万象登录名 = 云起 `sys_user.username` | 第一期不做自动建号 |
| 云起回调路径 | `/sso/callback` | 前端页，匿名可访问 |
| 云起换票 API | `POST /api/v1/auth/sso/exchange` | 无需登录、无需验证码 |

**密钥分工（必须遵守）：**

- 万象持有**私钥**，只用于签发 Ticket，私钥不出万象机房。
- 云起只登记**公钥**，只用于验签。
- 云起 `jwt.secret` **永不**交给万象。

## 1. 环境地址表（联调前填齐）

把下表填成双方「书面地址清单」。未填则不要进入对应环境联调。

| 用途 | 本地 | 测试 | 生产 |
|------|------|------|------|
| 云起前端 `{YUNQI_WEB}` | `http://localhost:3000` | `https://yunqi-test.example.com` | `https://yunqi.example.com` |
| 云起 API `{YUNQI_API}` | `http://localhost:8080` | `https://api-yunqi-test.example.com` | `https://api-yunqi.example.com` |
| 万象前端 | （本机万象地址） | （测试万象地址） | （生产万象地址） |
| 回调 URL 模板 | `{YUNQI_WEB}/sso/callback?ticket={ticket}&redirect=/home/dashboard` | 同左 | 同左（**必须 HTTPS**） |
| 换票 URL | `{YUNQI_API}/api/v1/auth/sso/exchange` | 同左 | 同左（**必须 HTTPS**） |

说明：

- `redirect` 只能是云起**站内相对路径**（以 `/` 开头），例如 `/home/dashboard`。禁止 `https://...`、`//evil`、反斜杠等。
- 生产禁止明文 HTTP 传 Ticket / 业务 JWT。

## 2. 云起侧准备（按顺序做）

### 2.1 确认功能已部署

云起仓库已落地：

- 后端：`POST /api/v1/auth/sso/exchange`
- 前端：`/sso/callback`
- 配置：`yunqi.sso.partners.wanxiang`

本地启动：

```text
后端：backend，profile=dev，端口 8080
前端：frontend，端口 3000（Vite 代理 /api → 8080）
```

### 2.2 登记万象公钥

**本地 / 开发：**

1. 公钥文件：`backend/yqap-core/src/main/resources/sso/wanxiang.pem`
2. 配置（`application.yml` 已默认开启）：

```yaml
yunqi:
  sso:
    enabled: true
    partners:
      wanxiang:
        enabled: true
        issuer: wanxiang
        public-key: classpath:sso/wanxiang.pem
        public-keys:
          wanxiang-2026: classpath:sso/wanxiang.pem
```

若万象提供的是**新公钥**（非仓库内开发钥）：

1. 用万象正式公钥覆盖 `wanxiang.pem`（或另存新文件并改配置路径）。
2. 与万象确认 `kid` 是否仍为 `wanxiang-2026`；若更换，更新 `public-keys` 映射。
3. 重启后端。

**测试 / 生产：**

1. 将万象公钥放到服务器安全目录，例如 `/etc/yunqi/sso/wanxiang.pem`（权限仅运行用户可读）。
2. 设置环境变量后启动（生产 `application-prod.yml`）：

| 变量 | 示例 | 说明 |
|------|------|------|
| `YUNQI_SSO_ENABLED` | `true` | 总开关，生产默认 `false` |
| `YUNQI_SSO_WANXIANG_ENABLED` | `true` | 万象来源开关 |
| `YUNQI_SSO_WANXIANG_PUBLIC_KEY` | `file:/etc/yunqi/sso/wanxiang.pem` | 公钥路径 |
| `YUNQI_SSO_AUDIENCE` | `yunqi-application-platform` | 一般不改 |
| `YUNQI_SSO_DEFAULT_REDIRECT` | `/home/dashboard` | 缺省跳转 |

生产切勿把私钥放进云起机器或配置中心。

### 2.3 预开通联调账号

在云起后台（或直接库表 `sys_user`）创建与万象**登录名一致**的用户，并授予角色。

建议至少准备：

| 用户名 | 状态 | 用途 |
|--------|------|------|
| `admin`（或双方约定账号） | 启用 | 正向联调 |
| 同名单号（如需） | 启用 | 业务角色验证 |
| `sso_disabled_user` | **禁用** | 负向：禁用账号不可登录 |

第一期：**无账号则换票失败**，不会自动建号。

### 2.4 把地址书面发给万象

发给万象的最小清单：

```text
回调：{YUNQI_WEB}/sso/callback
换票：{YUNQI_API}/api/v1/auth/sso/exchange
iss / aud / kid：见第 0 节
用户名规则：与云起 username 一致
```

## 3. 万象侧改造（按顺序做）

### 3.1 生成密钥对（万象机房执行）

```bash
openssl genrsa -out wanxiang-private.pem 2048
openssl rsa -in wanxiang-private.pem -pubout -out wanxiang-public.pem
```

- 将 **`wanxiang-public.pem`** 交给云起运维登记。
- **`wanxiang-private.pem`** 仅存万象密钥库 / KMS，禁止进 git、工单附件、聊天工具。

本地若先用云起仓库开发钥联调：私钥在 `docs/dev-keys/wanxiang-private.pem`（gitignore），**仅限本地**，上线前必须换成万象自持密钥。

### 3.2 已登录用户点击「进入云起」

服务端用私钥签发短期 Ticket（建议 TTL = 60 秒，上限 120 秒）。

**Header：**

```json
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "wanxiang-2026"
}
```

**Payload：**

```json
{
  "iss": "wanxiang",
  "aud": "yunqi-application-platform",
  "sub": "<与云起 username 一致>",
  "username": "<与云起 username 一致>",
  "name": "<可选显示名>",
  "iat": <unix秒>,
  "nbf": <unix秒, 通常等于 iat>,
  "exp": <iat + 60>,
  "jti": "<UUID>"
}
```

伪代码：

```text
now = unix_seconds()
ticket = jwt_sign_rs256(header, payload, wanxiang_private_key)
url = "{YUNQI_WEB}/sso/callback?ticket=" + url_encode(ticket) + "&redirect=/home/dashboard"
302 或 window.open(url)
```

注意：

- Ticket **不能**当作云起业务接口的 `Authorization: Bearer`。
- 不要用云起登录页的 `GET /api/v1/auth/public-key` 去加密 JSON 冒充 Ticket。
- 每次跳转使用新的 `jti`；同一 Ticket 只能换票一次。

### 3.3（可选）服务端直接换票

若万象后端代换票，再把云起业务 JWT 交给己方前端：

```http
POST {YUNQI_API}/api/v1/auth/sso/exchange
Content-Type: application/json

{
  "ticket": "<JWT>",
  "redirect": "/home/dashboard"
}
```

成功响应（与本地登录字段对齐）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "<云起业务JWT>",
    "expiration": 1774243200000,
    "redirect": "/home/dashboard"
  }
}
```

仍**不推荐**把业务 JWT 长期放在 URL 查询参数中。

## 4. 分环境联调流程

### 4.1 本地（无万象代码时，云起先自测）

1. 启动云起前后端（dev）。
2. 确认库中有目标用户且 `status=1`。
3. 仓库根目录签发 Ticket：

```powershell
.\docs\dev-keys\issue-ticket.ps1 -Issuer wanxiang -Username admin `
  -WebBase http://localhost:3000 `
  -Redirect /home/dashboard
```

4. 浏览器打开脚本打印的 `callback` URL。
5. 预期：短暂「正在登录」→ 进入工作台；地址栏不再残留 `ticket`。
6. 打开 DevTools → Application → Local Storage，应有 `token`、`tokenExpiration`。
7. 调用 `GET /api/v1/users/me` 应返回该用户。

### 4.2 本地（万象联调）

1. 云起登记万象提供的公钥（或双方约定先用开发钥）。
2. 双方时钟误差控制在 ±30 秒内（NTP）。
3. 万象用真实跳转打开 `{YUNQI_WEB}/sso/callback?...`。
4. 走第 5 节验收清单。

### 4.3 测试环境

1. 部署含 SSO 的云起版本。
2. 配置 `YUNQI_SSO_ENABLED=true` 与测试公钥路径。
3. 预开通测试账号；将测试 `{YUNQI_WEB}` / `{YUNQI_API}` 发给万象。
4. 万象配置指向测试回调地址（HTTPS）。
5. 从万象测试环境点「进入云起」完成端到端验证。
6. 查云起操作日志：登录渠道 `channel=WANXIANG`，方法为 `POST /api/v1/auth/sso/exchange`。

### 4.4 生产环境

1. 变更窗口：登记生产公钥、配置环境变量、预开通生产账号。
2. `YUNQI_SSO_ENABLED=true`，确认仅万象公钥生效。
3. 万象生产私钥独立保管；回调与 API 均为 HTTPS。
4. 先用专用联调账号做一次冒烟，再开放业务入口。
5. 保留本地密码登录（HYBRID），作为 SSO 故障兜底（是否在登录页展示由产品决定）。

回滚：将 `YUNQI_SSO_ENABLED=false` 或 `YUNQI_SSO_WANXIANG_ENABLED=false` 后重启即可关闭万象入口，不影响本地密码登录。

## 5. 验收清单（万象专项）

| # | 用例 | 预期 |
|---|------|------|
| 1 | 正确私钥、60 秒内换票 | 获得业务 JWT，进入云起 |
| 2 | 业务 JWT 调 `GET /api/v1/users/me` | 用户与菜单权限正确 |
| 3 | Ticket 当 Bearer 调业务 API | 失败（Ticket ≠ 业务 JWT） |
| 4 | 篡改 payload | 验签失败 |
| 5 | 过期 Ticket（>120s 或不在时钟差内） | 拒绝 |
| 6 | 同一 Ticket 第二次换票 | `票据已使用` |
| 7 | 错误 `aud` / 未登记 `iss` | 拒绝 |
| 8 | 云起无此用户 | `账号未开通` |
| 9 | 用户禁用 | `账号已被禁用` |
| 10 | `redirect=https://evil.com` | 400 或忽略并进默认首页 |
| 11 | 换票成功后地址栏 | 无 `ticket` 残留 |
| 12 | 操作日志 | `channel=WANXIANG` |

## 6. 常见失败对照

| 现象 / message | 优先检查 |
|----------------|----------|
| 未开启单点登录 | `yunqi.sso.enabled` / `YUNQI_SSO_ENABLED` |
| 未开通该来源的单点登录 | `partners.wanxiang.enabled`、`issuer` 是否为 `wanxiang` |
| 票据签名无效 | 公钥是否匹配、是否 RS256、是否用了登录页 RSA 公钥 |
| 票据接收方不正确 | `aud` 是否为 `yunqi-application-platform` |
| 票据无效或已过期 | 服务器时间、`exp`、时钟差 |
| 票据有效期超出限制 | `exp - iat` ≤ 120 |
| 票据已使用 | `jti` 重放 |
| 账号未开通 | 云起是否预创建同名用户 |
| 账号已被禁用 | `sys_user.status` |
| 回调地址不合法 | `redirect` 必须是站内 `/...` |
| 请求过于频繁 | IP 限流，稍后再试 |

详细原因在云起服务端日志；不要把验签细节回传浏览器。

## 7. 责任边界速查

| 事项 | 万象 | 云起 |
|------|------|------|
| 生成并保管私钥 | ✓ | — |
| 登记公钥、配置 `iss`/`kid` | — | ✓ |
| 签发 Ticket、浏览器跳转 | ✓ | — |
| 验签换票、签发业务 JWT | — | ✓ |
| 预开通 / 授权用户 | 提供名单 | ✓ 执行 |
| 本地密码登录兜底 | — | ✓ |
| 登出万象会话（反向登出） | 本期不做 | 本期不做 |
